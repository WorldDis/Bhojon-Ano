MASTER PROJECT PROMPT: BHOJON.FOOD

Act as a senior full-stack developer, UI/UX designer, database architect, and security engineer. Build a complete, responsive, production-oriented food ordering and employee management website named BHOJON.FOOD.

The website must be easy for a non-technical small restaurant owner to manage. Do not build just a static demo or frontend mockup. Implement working authentication, database operations, role-based permissions, order management, attendance, subscriptions, and export features.

1. Technology Stack and Free Hosting

Use the following stack:

- Frontend: Next.js with TypeScript and App Router.
- Styling: Tailwind CSS.
- Animation: Framer Motion.
- 3D elements: React Three Fiber or lightweight CSS 3D effects where appropriate.
- Backend and database: Supabase PostgreSQL.
- Authentication: Supabase Auth with secure role-based access.
- Hosting: Vercel free tier.
- Source control: GitHub.
- Spreadsheet exports: Excel-compatible XLSX and CSV.
- Cloud export: Google Drive API with secure OAuth integration.

Use free tiers wherever practical. The initial deployment must work on a Vercel-provided subdomain, such as "bhojon-food.vercel.app", if available.

Do not require a paid custom domain. Do not commit API keys, passwords, service-role keys, or OAuth secrets to GitHub.

Before implementing features, check current free-tier limitations and choose compatible solutions.

2. Brand Identity and Visual Design

Brand: BHOJON.FOOD

Tagline: "Ghar Jaisa Swad — Freshly Cooked, Daily"

Create a premium yet friendly combination of:

- Rustic Bengali village food culture.
- Traditional dhaba and countryside aesthetics.
- Warm cream, earthy brown, forest green, terracotta, and mustard yellow.
- Food photography, wooden textures, subtle leaf decorations, and elegant cards.
- Smooth 3D hover effects, floating food illustrations, scroll animations, and gentle transitions.
- A polished mobile-first interface with accessible text and buttons.

The website should look modern, attractive, and trustworthy, not childish or overly animated. Respect reduced-motion preferences and ensure animations do not make the website slow.

Create a consistent logo, favicon, typography system, buttons, forms, cards, loading states, and error messages.

4. Customer Ordering System

Implement a complete ordering workflow:

1. Customer browses the menu.
2. Customer selects dishes, quantities, and available meal slots.
3. Customer enters their name, mobile number, delivery address, and optional instructions.
4. Customer selects immediate ordering or a subscription plan, depending on availability.
5. The system validates meal availability, ordering deadlines, prices, and required details.
6. Customer submits the order.
7. The system generates a unique order ID.
8. The customer can view order confirmation and status.

Order statuses:

- Pending
- Confirmed
- Preparing
- Out for Delivery
- Delivered
- Cancelled

Provide an order history and order-status page. Do not claim that an order was submitted successfully unless the database confirms it.

Use a configurable payment method. Start with Cash on Delivery or Pay on Delivery. Do not simulate successful online payments. Integrate a payment provider only if properly configured.

5. Weekly and Monthly Subscriptions

Build an editable subscription management system.

The owner or authorized employee should be able to configure:

- Plan name.
- Weekly or monthly duration.
- Included meals.
- Price.
- Number of meals.
- Start and end dates.
- Delivery schedule.
- Customer details.
- Subscription status.
- Payment status.
- Renewal and cancellation details.

Calculate subscription totals correctly. Allow customers to view their active subscriptions and upcoming meals.

Do not invent automatic recurring payments. Initially, support manual payment tracking unless a real payment gateway is configured.

6. Three Separate Access Levels

Create three interfaces with different permissions:

A. Customer
B. Employee
C. Administrator

Authentication must be real, not simulated.

The public registration form must never allow anyone to create an administrator account.

Create the first administrator through a secure, documented setup process.

Employees must be invited or created by an administrator. Use secure password reset and account deactivation.

7. Employee Dashboard

Build a simple employee dashboard that works well on Android phones.

Main features:

- Employee profile.
- Daily attendance check-in and check-out.
- Attendance history.
- Working hours calculation.
- Late arrival and absence records.
- Leave requests and approval status.
- Assigned duties.
- Assigned order management.
- Menu and subscription editing, if the administrator grants permission.
- Personal salary information, if authorized.
- Downloadable personal attendance history.

Attendance requirements:

- Record date, check-in time, check-out time, and status.
- Prevent duplicate check-ins and invalid check-outs.
- Calculate total working hours.
- Record corrections with an audit trail.
- Use server-side timestamps.
- Record the authenticated employee ID for each attendance entry.
- Allow administrators to review and correct records with a recorded reason.

Do not treat a browser-generated timestamp as a trusted attendance record. If geolocation or a photo is used for attendance, make it optional and configurable.

9. Google Drive Integration and Excel Export

The administrator must be able to connect their own Google account through Google's official OAuth flow.

Add a dedicated Google Drive & Reports section.

Required export categories:

- Employee master list.
- Attendance daily report.
- Monthly attendance report.
- Salary report.
- PF report.
- Order list.
- Daily sales report.
- Weekly and monthly sales summary.
- Customer subscription list.
- Subscription payment history.
- Menu list.

Export requirements:

- XLSX format.
- CSV format.
- Date-range filtering.
- Employee filtering.
- Order-status filtering.
- Download to the administrator's device.
- Optional upload of the generated report to the administrator's authorized Google Drive folder.
- Display upload success or failure.
- Avoid duplicate or accidental overwriting of reports.
- Use clear filenames, such as "BHOJON_Attendance_2026-10.xlsx".

Create separate sheets in Excel where appropriate, with readable column headings, date formats, totals, and filters.

Do not ask for a Google password. Use OAuth, minimum required permissions, secure token handling, and server-side API calls. Allow the administrator to disconnect Google Drive.

Google Drive integration must be genuinely functional when credentials are configured; otherwise, clearly explain the remaining setup steps. Local XLSX and CSV exports must work independently.

10. Security and Privacy

This website will handle sensitive employee information.

Implement:

- Supabase Row Level Security (RLS).
- Server-side role and permission checks.
- Secure authentication and session handling.
- Least-privilege database access.
- Input validation and output encoding.
- Rate limiting for sensitive endpoints.
- Audit logs for important administrative changes.
- Safe file uploads with type and size validation.
- Private storage for employee documents.
- No public access to payroll, bank information, or government ID records.

Do not store Aadhaar numbers or bank details in public tables or expose them in ordinary employee lists. Prefer avoiding full Aadhaar storage entirely. If legally necessary, use an appropriate secure storage design, restricted access, masking, and encryption.

Only specifically authorized administrators should access sensitive employee records. Employees should only access their own permitted data.

Never include secrets in client-side code or exported reports unless explicitly authorized and necessary.

Provide database migrations, RLS policies, and seed data for development.

Never use sample records as real business data in production.

5. Update documentation.

Create a complete README explaining how to:

14. Acceptance Criteria

The project is not complete until:

- The public menu works on mobile and desktop.
- Customer orders are saved to the database.
- Customers cannot access employee or admin pages.
- Employees cannot access other employees' private records.
- Admin-only operations are enforced server-side.
- Employees can record attendance.
- Admin can manage employees, salary records, and PF records.
- Authorized users can update menus and subscription plans.
- XLSX and CSV exports contain actual database data.
- Google Drive upload works when properly configured.
- Sensitive data is not publicly accessible.
- The app builds successfully and deploys to Vercel.
- Setup instructions are sufficient for a beginner to follow.

Start by presenting the proposed architecture, database schema, project folder structure, and implementation plan. Then build the application with complete working code, not merely screenshots or a static prototype.

If a requested integration requires credentials, explain exactly how to configure it. Never pretend an unconfigured feature is working.

The final goal is a reliable, secure, beautiful, village-inspired food ordering and restaurant management platform that can grow with the BHOJON.FOOD business.
